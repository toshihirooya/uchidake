# 見ながら撮る写真と録画

## ねらい

見ていて「今だ」と思った瞬間を、手元の端末に写真や動画として残せるようにする。これまで録画は範囲外だった（理由の記録は無い）が、利用者の判断で入れる。

## 目標と、やらないこと

- 目標: 見る側の画面のボタンで、写真を 1 枚撮る・録画を始めて止める。できたものは手元の端末の「写真」アプリに入る。
- やらないこと: 見ていない間の録画（常時・時間指定・動きの検知）、カメラ側の端末への保存、アプリ内での一覧や再生、届いた映像より高い画質、録画の長さの上限、話しかけた自分の声の録音。
- 避けること: カメラの前にいる人に分からないまま録画できること。録画したのに保存されずに消えること。

## 検討した方法

| 方法 | 得失 | 採否 |
|---|---|---|
| すべて見る側で作る。届いた H.264 をそのままファイルに書き、写真は届いた映像から 1 コマを復元する | 見えているものがそのまま残る。変更は見る側にほぼ閉じる。画質は 640×480 で、コマが落ちた所は録画も止まって見える | 採用（利用者が選択） |
| カメラ側で高画質に撮って、ファイルを手元へ送る | 画質が良く、電波が悪くても途切れない。再送の無い今の通信に、ファイルを確実に届ける仕組みを足す必要がある | 不採用 |
| 写真だけカメラ側で撮って送り、録画は見る側 | 写真が高解像度になる。写真 1 枚を確実に届ける仕組みは要る | 不採用（あとから広げられる） |

## 設計

利用者が決めたこと: 見る側のボタンで撮る。上の表の 1 つ目の方法で作る。
それ以外は設計した側の判断。

### 写真

- 見る側は、最後のキーフレームから最新のコマまでの圧縮データを覚えておく（最長 2 秒ぶん、約 200KB）。
- 写真ボタンが押されたら、覚えているコマを `VTDecompressionSession` で順に復元し、最後の 1 コマを JPEG にして「写真」に追加する。ふだんは余分な復元をしない。
- 映像が止まっているとき（キーフレーム待ち）は、最後に表示できたコマが写真になる。
- 写真ボタンは、つながっているあいだだけ押せる（つなぎ直し中は押せない）。
- 撮れたら、画面を一瞬白く光らせて「写真を保存しました」と短く出す。

### 録画

- `AVAssetWriter` で MP4 を作る（書き終えてから閉じる、ふつうの MP4）。映像は届いた H.264 を圧縮し直さずに書く。音声はカメラから届いた PCM（16kHz・モノラル）を AAC にして書く。
- 録画ボタンを押すと、カメラにキーフレームを頼み、次のキーフレームから書き始める。
- コマの時刻は、届いた時刻（端末の時計）で付ける。コマが落ちた所は、直前のコマが止まって見える。音声は届いた順に連続で並べ、届いた時刻とのずれが大きくなったら届いた時刻に合わせ直す（そこは無音になる）。
- 映像の大きさが変わったとき（カメラの端末の向きが変わったとき）は、そこでファイルを閉じて保存し、続きを新しいファイルに書く。1 本の MP4 の途中では大きさを変えられないため。
- つなぎ直しのあいだも録画は続ける。届かなかった時間は、止まった映像と無音になる。そのあいだも録画を止めるボタンは押せる。録画を始められるのは、つながっているあいだだけ。
- 止めるのは、もう一度ボタンを押したとき、画面を閉じたとき、アプリがバックグラウンドに回ったとき、端末の空き容量が少なくなったとき。どの場合も、そこまでを保存する。保存が終わるまでの時間は `beginBackgroundTask` で確保する。
- 空き容量は録画中に見張り、残りが少なくなったら（目安 200MB）自分で止めて保存する。`AVAssetWriter` は書き込みに失敗するとファイルを閉じられず、そこまでの録画が再生できなくなるので、失敗する前に止める。空き容量がこの目安より少ないときは、録画を始めない。
- 画面を閉じるのは待たせない。ファイルを閉じて「写真」に入れる処理は、見ている画面より長く生きる持ち主（アプリ全体で 1 つ）が続け、結果はカメラの一覧の画面に短く出す。
- 「写真」への追加に失敗したときは、一時ファイルを消さずに残し、次にアプリを開いたときにもう一度追加を試す。
- スピーカーを消していても、録画にはカメラの音が入る。
- 録画中は、赤い印と経過時間を画面に出す。保存できたら「動画を保存しました」と出す。
- 一時ファイルはアプリ専用のフォルダ（システムに勝手に消されない場所）に作り、「写真」に入ったら消す。
- 録画の途中でアプリが落ちたり強制終了されたりすると、そのときの録画は失われる（閉じていない MP4 は再生できない）。起動時に、閉じられていないファイルは消す。これは既知の制限として `docs/spec.md` の 10 章に書く。

### 「写真」への保存と許可

- `PHPhotoLibrary` の「追加のみ」の許可を使う。`NSPhotoLibraryAddUsageDescription` を足す。
- 許可は、最初に写真か録画のボタンを押したときに求める。録画は、許可が取れてから始める（録り終わってから断られて消える、を避ける）。
- 断られているときは、設定アプリで許可するよう案内を出し、撮らない。

### カメラ側への通知（通信の変更）

- 生存通知（種類 4）の後ろに、1 バイトのフラグを足す。ビット 0 が「この端末は録画中」。フラグの無い生存通知は「録画していない」と読む。
- カメラは、見る側ごとにこのフラグを覚える。その見る側が切れたら、録画していない扱いに戻す。
- 状態（種類 5）の JSON に、録画中の見る側の数 `recorders` を足す。無ければ 0 と読む。
- カメラの画面は、`recorders` が 1 以上のあいだ「録画中」を出す。動作中の表示と同じく、画面を暗くしても消さない。
- 見る側の画面も、ほかの端末が録画しているときは、視聴台数の横にそれを出す。
- 写真はカメラ側に知らせない。
- 古い版の端末と混ざっても壊れない（古いカメラはフラグを無視する。古い見る側は `recorders` を無視する）。ただし古いカメラには「録画中」が出ないので、全端末を更新して使うものとする。

### 画面

見る側の操作の列の上に、写真と録画のボタンを足す。

```
[リビング 80% / 1台が視聴中]  ● 0:12     [×]

                 （映像）

            [写真]      [録画]
     [音]     [ 押して話す ]     [切替]
```

### そのほか

- 文言は日本語を元に、英語も `Localizable.xcstrings` と `InfoPlist.xcstrings` に足す。
- デバッグビルド限定の起動オプションを足す: `-autoPhoto`（つながったら写真を 1 枚撮る）、`-autoRecord <秒>`（つながったらその秒数だけ録画する）。結果は `[Uchidake]` の行に出す。シミュレータの「写真」の許可は `xcrun simctl privacy <UDID> grant photos-add com.example.Uchidake` で与える。
- シミュレータでは、テスト画像と確認音のデータがそのまま写真と動画になる。
- `docs/spec.md` を直す: 1 章（録画と写真を「入れるもの」へ。見ていない間の録画は「入れないもの」に残す）、5 章（生存通知と状態）、6 章（録画中の表示）、7 章（写真と録画）、9 章（起動オプション）、10 章（録画の画質と途切れ）。
- 単体テスト: 生存通知のフラグと `recorders` の読み書き（古い形式を含む）、コマを覚える部分、録画の時刻付け。圧縮したテスト画像から実際に写真と MP4 ができることも、シミュレータのテストで確かめる。

## 実装する人に任せること

型とファイルの分け方（`recorders` は、無いときに 0 と読むよう自前で復号する。写真の許可の文言は `project.yml` に足す）、ボタンの見た目と文言、JPEG の品質と AAC のビットレート、音声の時刻を合わせ直すしきい値、保存に失敗したときの文言。
